# CLAUDE.md — mobile-recipes

Personal recipe site for Kate and Pat. Built with Jekyll, deployed to GitHub Pages.

---

## Project overview

- **Purpose**: A simple, mobile-friendly recipe reference site for personal use
- **Hosting**: GitHub Pages — the site builds automatically on push to the main branch
- **Philosophy**: Keep it simple. Avoid complex logic, plugins, or heavy dependencies. If a feature needs a plugin or a framework, question whether it's needed at all.

---

## Tech stack

- **Jekyll 3.9.0** — pinned to this version for GitHub Pages compatibility. Do not upgrade.
- **Kramdown + GFM** — Markdown parser
- **Sass** — single file: `_sass/main.scss`, compiled to `assets/css/styles.css`
- **No JavaScript libraries** — vanilla JS only
- **No Jekyll plugins** — GitHub Pages only supports a small whitelist of plugins. The tag system works around this with a Python script (see below).

## Repository structure

```
_recipes/          # One Markdown file per recipe
_layouts/
  default.html     # Base layout (nav + wrapper)
  recipe.html      # Wraps default; splits content at <!-- break -->
  tagpage.html     # Lists recipes for a given tag
_includes/
  head.html        # <head> meta and CSS link
  navigation.html  # Top nav bar (driven by _data/navigation.yml)
  tagcloud.html    # Renders all tags as links
  collecttags.html # Liquid snippet that aggregates tags across all recipes
_sass/
  main.scss        # All styles — single file, no partials
_data/
  navigation.yml   # Nav bar links
tag/               # Auto-generated tag pages — do not edit manually
assets/
  css/             # Compiled CSS output
  favicons/        # Site icons
index.html         # Home page with client-side search
recipes.html       # Alphabetical recipe list
tag_generator.py   # Script to regenerate tag/ pages
```

## Recipe format

Each recipe is a Markdown file in `_recipes/`. The filename becomes the URL slug.

```markdown
---
name: Recipe Name Here
tags: tag1 tag2 multi-word-tag
---

## What you need

* Ingredient one
* Ingredient two

<!-- break -->

## How it's done

Method goes here.
```

### Frontmatter rules

- `name` — the display name of the recipe. Title case. This is what appears in search and lists.
- `tags` — **space-separated string, not a YAML array**. This is intentional; the tag system depends on this format. Multi-word tags use hyphens (e.g. `slow-cooker`, `one-pot`).

### The `<!-- break -->` separator

The recipe layout splits content on `<!-- break -->`. Everything before it renders in the **ingredients column** (left/top), everything after in the **method column** (right/bottom). On screens narrower than 700px, this collapses to a single column.

If a recipe has no `<!-- break -->`, the content renders full-width without columns.

## Tag system

GitHub Pages doesn't support Jekyll plugins, so tag pages are pre-generated by a Python script rather than built by Jekyll at compile time.

**After adding a new tag to any recipe, run:**

```sh
python tag_generator.py
```

This script:
1. Reads all `_recipes/*.md` files
2. Collects every unique tag
3. Deletes and recreates all files in `tag/`

The generated files in `tag/` must be committed alongside recipe changes. Never edit files in `tag/` manually — they will be overwritten.

If a tag already exists (i.e. its tag page is already in `tag/`) and you're just adding a recipe that uses it, you don't need to re-run the script.

## Navigation

Navigation links are defined in `_data/navigation.yml`:

```yaml
- name: Home
  link: /
- name: Recipes
  link: /recipes.html
```

Add new top-level pages here if needed. Keep the nav minimal.

## Styling

All styles live in `_sass/main.scss`. There are no partials — keep it that way unless the file grows substantially.

Key layout decisions:
- `.wrapper` constrains content to `max-width: 50em` and centres it
- `.container` is a two-column grid for the recipe layout (ingredients | method)
- The grid collapses to a single column at `max-width: 700px`
- The nav is fixed at the top; `body` has `padding-top: 60px` to compensate

Avoid adding CSS frameworks or utility libraries.

---

## Client-side search

The home page (`index.html`) builds a JSON array of all recipes (name, tags, URL) using Liquid at build time, then filters it in vanilla JS as the user types. There is no backend and no search index.

Keep search logic simple. The current approach — regex match against name and tags — is intentional.

---

## Adding a recipe — checklist

1. Create `_recipes/your-recipe-name.md` using the format above
2. If you're introducing a new tag, run `python tag_generator.py` and commit the new file(s) in `tag/`
3. Commit and push — GitHub Pages builds and deploys automatically

---

## What to avoid

- **Jekyll plugins** — they won't run on GitHub Pages
- **JavaScript libraries** — jQuery, React, etc. are not needed here
- **CSS frameworks** — Tailwind, Bootstrap, etc. are overkill for this site
- **Splitting `main.scss` into partials** — unnecessary complexity at this scale
- **YAML arrays for tags** — tags must be a space-separated string; changing this breaks `collecttags.html` and `tag_generator.py`
- **Editing files in `tag/` manually** — always use `tag_generator.py`
- **Complex Liquid logic** — if a template is getting complicated, simplify the approach
